# recording-frame 验证记录

2026-10-19，macOS Apple Silicon，Python 3.12.9，PyAV 17.1.0。
程序和本次更新后的测试都不调用外部 ffmpeg / ffprobe；H.264、MPEG-4 和 AAC 样本由 PyAV wheel 的编解码库生成。

## 真实长录播随机读取

来源为当前已授权账号可访问的智云课程 `89418`、堂次 `2019095`、分段 `1`。
现有本地 MP4 与服务器媒体的大小均为 **2,834,281,001 字节**。
视频为 H.264、1920×1080，视频流时长 **13725.047 秒**（约 3 小时 49 分钟）。
文件头部 moov 的大小为 **11,185,244 字节**；读取索引是该样本的主要开销。
没有重新下载完整视频，也没有把课程视频或截图加入仓库。

全部测量均请求 `13680 / 13682 / 13684` 秒，即 `03:48:00 / 03:48:02 / 03:48:04`，接近视频尾部，每次输出 3 张 JPEG。

| 输入来源 / 读取块 | 媒体请求数 | 实际响应体字节 | 提取耗时 | 进程峰值 RSS |
| --- | ---: | ---: | ---: | ---: |
| 已有本地 MP4，首次验证 | 0 | 0 | 0.408 秒 | 未测量 |
| 智云远端，256 KiB（调优前） | 49 | 12,582,928 | 27.594 秒 | 未测量 |
| 智云远端，1 MiB | 13 | 12,582,928 | 19.014 秒 | 未测量 |
| 完整 `./zju.py recording-frame … --json`，1 MiB | 13 | 12,582,928 | 20.254 秒 | 未测量 |
| 本地 MP4，加入请求级 sidecar 元数据后 | 0 | 0 | 0.505 秒 | 199.97 MiB |
| 智云远端，加入请求级 sidecar 元数据后，1 MiB | 13 | 12,582,928 | 22.008 秒 | 218.34 MiB |

耗时是程序 `elapsed_sec`，包括打开/索引/解码/编码/图片与元数据写入，不包括之前的学校认证和课程查询。
请求数与字节只统计媒体 Range GET，不含认证/API 调用及 HTTP 标头。
失败重试收到的响应体也计入预算。12,582,928 字节约 12 MiB，是整个视频的 **0.444%**。
网络条件有波动，这些是实际运行值，不是速度承诺，也不代表不同课程有相同索引大小。

RSS 在各自独立 Python 进程中用 `resource.getrusage(resource.RUSAGE_SELF).ru_maxrss` 测量，macOS 返回字节，除以 2²⁰。
这是包含 Python、模块、原生库、MP4 索引、解码器及输出图像的整个进程高水位，不是 Range 缓存大小，也不是纯解码增量。
Range 数据缓存另有固定的 8 MiB 上限；索引和解码器还会占用额外内存。

返回的实际显示时间依次为 **13679.995 / 13681.995 / 13683.988 秒**，timebase 为 `1/16000`。
单次容器只 seek 1 次，解码 112 帧，共用相邻目标的解码结果。
本地与远端三张 JPEG 的 SHA-256 逐张完全一致，并已查看其中一张确认为真实教室画面，输出分辨率保持 1920×1080。

可在账号有该堂次权限时复现：

```bash
./zju.py recording-frame --course 89418 --sub 2019095 \
  --at 03:48:00 --at 03:48:02 --at 03:48:04 --json
```

不指定图片位置时写到新的系统临时目录，CLI 退出后保留，调用方可自行删除。
若标准录播目录及下载清单已经有该文件，命令会选本地；测远端时应使用一个没有对应已完成录播的 `--out` 根目录。
该根目录只参与本地来源查找，截图仍放在系统临时目录。

## 离线正确性及异常验证

运行完整测试（全部 fixture 由 Python wheel 生成）：

```bash
uv run --with requests --with httpx --with img2pdf --with pillow --with keyring --with numpy --with 'av>=16,<18' \
  python -m unittest discover -s tests -v
```

`tests/test_recording_frames.py` 使用确定的彩色帧序号、长 GOP 和 B 帧，读取 JPEG 像素确认输出确实来自目标帧，而非只检查图片是否生成。
另有非零起始 PTS 和可变帧间隔样本：目标位于长显示间隔内时必须仍取前一张实际显示帧。
本地 HTTP 服务器检查 Range 位置、字节统计及 If-Range，分别覆盖头部/尾部 moov；尾部截图的读取量必须明显小于完整测试视频。

最终完整测试共 65 项（其中影格提取测试 17 项），全部通过；运行中拦截外部 ffmpeg / ffprobe 调用，未触发拦截。旧音频测试也已改用 PyAV 生成样本并校验 AAC 压缩数据 SHA-256。

覆盖的主要边界：

- 本地/远端精确定位、非关键帧、B 帧、非零起点、VFR、最后一帧和越界错误。
- 相邻时间共用容器/缓存/解码器，远距离目标重新 seek，避免每帧重开视频。
- 200 与重定向在读取响应体前拒绝；401/403、错误 Content-Range、错误长度、截断、超时/断线重试、源版本变化及流量上限。
- 重试收到的部分响应体累计计数，读取缓存有界，客户端不带学校 Cookie 或 Authorization。
- 分段选择、本地完成清单优先、未完成 `.part` 不使用、其他 CLI 回归。
- 默认临时目录位于系统临时位置、每次唯一、子进程退出后图片仍存在、不写入课程同步根目录。
- 单张完整路径、相对路径、批量目录、逐张不同目录、空格/中文/`=`/Windows 路径解析、非法组合及重复路径。
- 课程/堂次/分段名称隔离、同毫秒及重复时间冲突、有效缓存、图片损坏、源变化、签名 URL 刷新与 `--force`。
- 图片编码失败及发布冲突不覆盖原文件，不留下半张图片；JSON 可直接解析，并映射到实际文件。
- 图片 sidecar 保存逐帧元数据和生成请求的网络/耗时统计，不保存签名、Cookie 或 Authorization。

## 尚未实机验证和范围限制

本次实机验证仅 macOS Apple Silicon。Windows 和 Linux 依赖 PyAV 预编译 wheel 及标准跨平台文件 API，尚未在本次任务中实机运行。
真实长视频验证使用 H.264；H.265 依赖 wheel 所带解码器，本次未以真实智云 H.265 素材验证。
当前面向带可随机访问索引和已知视频流时长的普通 MP4，不承诺 HLS、直播或损坏/缺索引媒体。
远端必须有强 ETag 或 Last-Modified，以及与范围一致的固定 Content-Length（不接受无长度的 chunked 回应）；不支持 Range、缺少版本标识、重定向、源变化或预算不足会明确停止，不回退到整文件下载。
默认无跨次全局截图数据库；仅指定目录/完整路径时可通过图片旁的 JSON 校验并复用。
大量目标、极长 GOP 或极大的 moov 可能需要提高 `--max-fetch-mb`；不会默默解除预算。
